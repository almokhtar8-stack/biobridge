# BioBridge 2.0 educational coverage matrix

This file is generated by `node tools/build_coverage.mjs` from the content files, so the numbers match the site exactly. Course module titles and summaries come from the public Coursera course pages (checked 7 November 2026). BioBridge is an independent study companion: nothing here is an official KAUST Academy, KAUST, Rice, IBM or Coursera blueprint, and no real assessment questions were used or seen.

## How to read it

- **Core**: the lesson teaches something the linked course module teaches.
- **Support**: background the courses assume or only touch briefly (for example the biology behind RNA-seq).
- **Beyond**: goes past the three courses. Learners see a "Beyond the prerequisites" label on these lessons.
- **Bank L1/L2/L3**: hand-written practice questions at beginner, intermediate and application level. Every option has its own explanation, and every question that contains code was executed with real Python, R or Bash to confirm its answer.
- **Generated**: question templates that produce fresh numbers or sequences each time (seeded, so a session can be reproduced). Their answers are computed, and the code-based ones were executed during testing.
- Lesson checks (the two or three questions at the end of each lesson) are counted separately from the bank.

## Lessons that go beyond the three courses

- Command-line recipes for biological files (`f1-bio-recipes`): search text with grep and its options; combine commands with pipes and redirect output to files; sort, count and extract columns with sort, uniq, cut and tr.
- Mini-project: a small sequence toolkit (`f2-bio-project`): apply python to small biological sequence problems.
- What real analysis workflows look like (`f3-workflows`): describe what real analysis workflows and tools do.

These are labelled "Beyond the prerequisites" on the lesson page and in lesson lists. They exist because they connect the course skills to real biological files and workflows. The first two practice core course skills (grep, pipes, Python strings and loops) on biological files, so their questions can appear in mock assessments. Objectives flagged `beyond: true` in `content/curriculum.js` (currently only BI.WORKFLOW) are left out of mocks and appear only in topic practice and review.

## Gaps and thin spots

Computed automatically: any objective with fewer than 4 bank questions, or with no application-level (L3) question.

- None. Every objective has at least 4 bank questions and at least one application-level question.

Known gaps that numbers cannot show:

- **RStudio and R Markdown**: explained in words with example code, but there is no R engine in the browser, so R code is shown with its real, pre-computed output rather than run live.
- **Linear models and ANOVA**: covered conceptually with verified R output; there is no interactive ANOVA lab.
- **Networking and package managers** (`ping`, `curl`, `wget`, `apt`): the simulated terminal has no network or installer, so these commands print an explanation instead of running.
- **Vim**: described and compared with nano; the in-browser editor is a simple text box, not a modal editor.
- **Full pipelines** (aligners, quantifiers, DESeq2, Scanpy): described in the workflows lesson and the guided experiment, but not run, because they need real reference genomes and far more memory than a browser offers.
- **Course-specific details** that change between course runs (quiz formats, lab tools, project rubrics) are deliberately not reproduced.
